# City Life Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the 3D pointer city live: workplaces that grow by demand, residents who commute and run errands on foot and by car on the real clock, sun and cloud shadows, real weather for a city the player types, rivers with bridges, and an industrial zone — within a stated CPU ceiling.

**Architecture:** Everything that decides *what exists* stays in the pure, tested sim (`src/sims/`): kinds and capacities, world seed and water, resident–job pairing, daily trips and positions as pure functions of time. The Three.js view (`src/render/`) only draws what is near the camera, at up to 60 fps in the 3D window while anything moves (from Task 4b; Task 4 had capped traffic at 10 fps), as a 2D edge sketch when docked, and not at all when hidden. Rust gains a data-folder override for tests and two small files (world seed, weather place). Weather is fetched from Open-Meteo by the webview.

**Tech Stack:** TypeScript 5.9, Vite 8, Three.js 0.186.1, vitest 5, Tauri v2 + Rust, Kenney City Kit (Suburban, Commercial, Roads, Industrial, Car Kit; CC0).

**Spec:** `docs/specs/2026-11-03-city-life-design.md` (builds on `docs/specs/2026-11-03-iso-city-design.md`)

## Global Constraints

- Branch `city-life`; one commit per task; never push.
- Order (Kia): people and cars first — Tasks 1–4 before anything else.
- Kinds stay fixed at birth; every new lot still draws exactly three random numbers (chance, delay, roll); any rule change bumps `CITY_RULES_VERSION` (regrow from records is accepted).
- Clock: sky, shadows and trips follow this Mac's clock; the T key previews the sky only.
- Cost by window mode (replaces the 15% ceiling from Task 4b on). In 3D, everything (the roller, traffic, later water, clouds and weather) draws at up to 60 fps, with no ceiling; it is measured and reported. The edge sketch costs ≤ 7% for capture plus both WebKit processes. A hidden window draws no frames. In every mode, a parked city with nothing moving draws no frames.
- Real-window CPU samples from Task 4b on are batched into Task 9, so Kia's own window is closed once, at a time he picks. A task may run a second test window beside his for functional checks, but never measures CPU while his window runs.
- Dev and measurement runs set `TRACKPAD_DATA_DIR` to a scratch folder holding a generated test city; nothing touches `~/Library/Application Support/edu.nyu.kiabai.trackpad/`, and existing files in `prototypes/data` are never deleted or edited (the generated test city may be written to the gitignored `prototypes/data/test-city/`). Never script the real pointer.
- Budgets: ≤ ~400 cars and ~600 people drawn; path finding ≤ 5 ms per frame; paths cached until `sim.version` changes.
- No streaks, notifications, toasts or guilt; offline weather shows clear sky with no error.

## Review Focus

1. A brand-new city (0–5 houses, no workplaces) at 08:00: nobody is stuck or drawn at NaN, residents with no job still go out on errands. → Task 2 test "unemployed residents still get errands"; Task 3 test "no workplace, no commute, no crash".
2. Road cut in two by flattening (or a river): a trip whose ends are not connected is skipped, not drawn walking through houses. → Task 2 test "unreachable trip is dropped".
3. Midnight and day rollover: trips are computed per local day; a trip that starts 23:50 and ends after midnight still moves. → Task 2 test "trip across midnight".
4. Typed city not found / offline / API error: weather stays clear, the overlay can be reopened, nothing throws in the frame loop. → Task 6 tests "unknown city", "fetch failure keeps last weather".
5. Snapshot from before this plan (rules v3): ignored, city regrows; the world seed is created once and never changes afterwards. → Task 7 test "seed survives restore; v3 snapshot rejected".

### Task 4b: Window modes — 3D, the edge sketch, nothing when hidden

Spec section *Window modes*. Kia's order: before Task 5.

**Files:**
- Create: `src/modes.ts` (pure: the mode machine and the dock geometry) and `src/render/sketch.ts` (a Canvas2D sketch, plus a pure helper that lists what to draw).
- Modify:
  - `src/window.ts`: wiring, the collapse button, the gear popover with "Always 3D", hover and leave timers, and stopping on `visibilitychange`.
  - `src/render/city3d.ts`: everything at up to 60 fps, the `TRAFFIC_FPS` gate removed, and `pause()`/`resume()`.
  - `src/window.css`.
  - Capture `tauri.conf.json` and `capabilities/default.json`: only the window permissions the code calls, such as set-size, set-position, outer-position, current-monitor and the moved event.
- Test: `test/modes.test.ts`, `test/sketch.test.ts`.

**Interfaces:**
- `type Mode = "full" | "edge" | "peek" | "hidden"`. `full` is the open window, `edge` the docked sketch, and `peek` an edge window opened by hovering.
- `step(state: ModeState, ev: ModeEvent, settings: { always3d: boolean }): ModeState`. Events:
  - `moved(rect, monitor)`, `collapse`, `pointerIn(t)`, `pointerOut(t)`, `click`, `tick(t)`
  - `visibility(hidden: boolean)`: hidden from any mode returns to that mode when shown.
- `dockRect(side: "left" | "right", y: number, monitor: Rect): Rect` returns 160 × 120 pt flush to that side of the monitor's visible frame, clamped vertically. `nearEdge(rect, monitor, 24)` returns `"left" | "right" | null`. A peek's 512 × 380 rect grows inward from the docked side.
- Timing: hover ≥ 500 ms opens a peek. Pointer out for ≥ 2000 ms ends it and returns to edge. Click opens to `full`, which stays.
- `sketchItems(sim, centre, radius)` returns road segments (cell to neighbour, with tier) and lots (cell, kind) inside the 3D close-up's area, plus the roller.
- `drawSketch(ctx, items, { night })` draws them in the diamond projection. It redraws when `sim.version` changes or the roller crosses a cell, at most 4 per second, and the WebGL canvas is not drawn meanwhile.
- Hover may be read from the webview's mouse events or from the captured pointer against the window rect. It is the builder's call; say which in the report.
