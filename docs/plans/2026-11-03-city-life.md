# City Life Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the 3D pointer city live: workplaces that grow by demand, residents who commute and run errands on foot and by car on the real clock, sun and cloud shadows, real weather for a city the player types, rivers with bridges, and an industrial zone — within a stated CPU ceiling.

**Architecture:** Everything that decides *what exists* stays in the pure, tested sim (`src/sims/`): kinds and capacities, world seed and water, resident–job pairing, daily trips and positions as pure functions of time. The Three.js view (`src/render/`) only draws what is near the camera, now at up to 15 fps while anything moves. Rust gains a data-folder override for tests and two small files (world seed, weather place). Weather is fetched from Open-Meteo by the webview.

**Tech Stack:** TypeScript 5.9, Vite 8, Three.js 0.186.1, vitest 5, Tauri v2 + Rust, Kenney City Kit (Suburban, Commercial, Roads, Industrial, Car Kit; CC0).

**Spec:** `docs/specs/2026-11-03-city-life-design.md` (builds on `docs/specs/2026-11-03-iso-city-design.md`)

## Global Constraints

- Branch `city-life`; one commit per task; never push.
- Order (Kia): people and cars first — Tasks 1–4 before anything else.
- Kinds stay fixed at birth; every new lot still draws exactly three random numbers (chance, delay, roll); any rule change bumps `CITY_RULES_VERSION` (regrow from records is accepted).
- Clock: sky, shadows and trips follow this Mac's clock; the T key previews the sky only.
- Cost ceiling: with traffic running, capture + both WebKit processes ≤ 15% CPU in the real window; parked with nothing moving draws no frames. Cut order if over: shadow map size → shadows off when zoomed out → weather particle counts → 15 → 10 fps → agent counts.
- Motion draws at most 15 fps (the roller keeps up to 30).
- Dev and measurement runs set `TRACKPAD_DATA_DIR` to a scratch folder holding a generated test city; nothing touches `~/Library/Application Support/edu.nyu.kiabai.trackpad/`, and existing files in `prototypes/data` are never deleted or edited (the generated test city may be written to the gitignored `prototypes/data/test-city/`). Never script the real pointer.
- Budgets: ≤ ~400 cars and ~600 people drawn; path finding ≤ 5 ms per frame; paths cached until `sim.version` changes.
- No streaks, notifications, toasts or guilt; offline weather shows clear sky with no error.

## Review Focus

1. A brand-new city (0–5 houses, no workplaces) at 08:00: nobody is stuck or drawn at NaN, residents with no job still go out on errands. → Task 2 test "unemployed residents still get errands"; Task 3 test "no workplace, no commute, no crash".
2. Road cut in two by flattening (or a river): a trip whose ends are not connected is skipped, not drawn walking through houses. → Task 2 test "unreachable trip is dropped".
3. Midnight and day rollover: trips are computed per local day; a trip that starts 23:50 and ends after midnight still moves. → Task 2 test "trip across midnight".
4. Typed city not found / offline / API error: weather stays clear, the overlay can be reopened, nothing throws in the frame loop. → Task 6 tests "unknown city", "fetch failure keeps last weather".
5. Snapshot from before this plan (rules v3): ignored, city regrows; the world seed is created once and never changes afterwards. → Task 7 test "seed survives restore; v3 snapshot rejected".

### Task 2: Workplaces by demand, capacities, and the daily trips (pure)

**Files:**
- Modify: `src/sims/kinds.ts` (add `"office"`; shops leave `UNLOCKS`), `src/sims/city.ts` (demand counters, workplace choice in `kindOfNewLot`), `src/config.ts` (`CITY_RULES_VERSION = 4`)
- Create: `src/sims/people.ts`
- Test: `test/kinds.test.ts`, `test/city.test.ts`, `test/people.test.ts`

**Interfaces:**
- `RESIDENTS: Record<"house" | "row" | "detached" | "apartment", readonly [number, number, number]>` by tier = house [2,4,6], row [3,3,3], detached [2,3,4], apartment [2,4,20]; `JOBS: Record<"shop" | "office" | "landmark", number>` = shop 4, office 12, landmark 30 (industry added in Task 8).
- `CitySim.demand(): { residents: number; jobs: number }` counted at tier-3 capacity, updated when lots are made or flattened (and snapshotted).
- `kindFor` gains `demand` and `besideAvenue: boolean`: when `residents > 1.2 × jobs`, the lot is a workplace with chance 0.5 (else 0.1), drawn from the existing `roll`; a workplace is a `shop` at a corner or beside an avenue, else an `office`.
- `people.ts`: `residentsOf(sim, t)` → `{ id, home: [x, y] }[]`; `jobsOf(sim)` → `{ id, work: [x, y] }[]`; `assignJobs(residents, jobs, seed)` → `Map<residentId, jobId | null>` (nearest free job by grid distance, seeded tie-break; my call: grid distance, not road distance, for cost); `tripsForDay(residentId, home, work, dayStartMs, seed)` → `Trip[]` with `{ from, to, depart, purpose: "work" | "home" | "errand" }` (out 07:00–09:30, back 16:30–19:00, errands so that ~25% of residents are out in 10:00–16:00, few after 21:00); `roadPath(isRoad, from, to, maxNodes = 4000)` → cells or null (BFS from the road beside each lot); `positionAt(path, depart, speedCellsPerSec, t)` → `{ x, y, heading } | null`; walking when the path ≤ 8 cells (1.2 cells/s), else driving (4 cells/s).

### Task 5: Sun and cloud shadows

**Interfaces:** `sunDirection(d: Date, sunrise?: number, sunset?: number): { azimuth, elevation }` (pure; elevation ≤ 0 means no sun); directional light with `castShadow`, a 1024² PCF soft shadow map whose camera follows the view; buildings, cars and the roller cast, ground and roads receive; `cloudShadow` term (scrolling noise in world XZ, amount and drift from the weather state, defaulting to light drift) added to the ground and the patched building shaders.
